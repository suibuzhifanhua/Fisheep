# 功能拓展路线图（8 个方向 · 分阶段实施计划）

> v1.0.755 建立。**本文件是「拓展出计划」的交付物**：8 个方向只写分阶段计划与验收判据，
> **本轮不实现任何方向的架构骨架**。出处见 `Fisheep_项目评审与拓展方向.md` 第五节。
>
> 与 `docs/deferred.md` 配套：这里写「准备怎么做、按什么顺序」，那里写「哪些有意没做、
> 什么条件下才动」。评审报告里的 P0/P1/P2 改进已全部字面落地，逐条验收见 `docs/评审改进意见_字面补做验收.md`。

## 0. 总原则

1. **不搞大爆炸重构**：每个方向拆成可独立回滚的小批次，每批次走 `AGENTS.md` 的完整
   验证栈（py_compile → node --check / 前端门禁 → 全量 pytest → `build.py --yes` → 实跑）。
2. **企微 profile 零行为变化**：任何抽象层上线，第一个验收判据都是「企微原有场景
   100% 不退化」，再加第二个目标应用跑通一条最小链路。
3. **棘轮只许下降**：巨型函数基线、裸 except 基线、新增的 `HIGH_RISK` 契约清单，
   都只许加保护不许松一格。
4. **每个抽取都配「改回旧写法必红」的行为锁**（本轮 5 份契约测试已示范这个套路）。
5. **不引入 npm/Vite/webpack 构建链**（v1.0.756 起前端已是原生 ES Module：
   单一 `type="module"` 入口 `js/_entry.js` + 18 个模块副作用 import，仍不引打包器）。

## 1. 依赖关系与阶段总览

```
阶段 A（本轮已落地：地基）

  P2 发布与迁移规范/注释数字门禁 · deferred 登记机制
        │

        │
        ├──────────────► 阶段 C（生态与信任层）
        │                 方向 2 技能包标准化 + DAG（依赖方向 1 的工具子集抽象）
        │                 方向 5 审批待办中心 / 计划模式
        │                 方向 7 数据边界看板 + 离线硬开关
        │
        └──────────────► 阶段 D（边界拓展与评估，不做产品承诺）
                          方向 6 受控模式 + 跨平台架构解耦

```

| 阶段 | 目标 | 进入下一阶段的判据 |
|---|---|---|
| A 地基 | 让后续重构有可验证的安全网 | 门禁全绿、契约覆盖 5/5、`run_id` 可一次查询完整调用链 |
| B 平台化 | 从「企微专用」走向「通用桌面自动化」，且效果可度量 | 第二个目标应用跑通最小链路；评测集给出首份基线对比表 |
| C 生态/信任 | 能力可配置、可接管、可举证隐私 | 新审计场景用配置接入而非改 1990 行 Python；离线开关实测阻断所有非 localhost 出站 |
| D 边界 | 架构解耦与团队能力 | Win32 依赖收进 `platform/`；健康中心能自动归因一次历史故障 |

## 2. 阶段 B 详情

### 方向 1｜目标应用适配器 `TargetProfile` ★最高优先

- **现状地基**：`wecom_bridge/`、CDP 端口策略、`cdp_is_wecom` UA 校验、窗口匹配、
  选择器策略、下载通道、技能提示词、`SKILLS` 场景文案全硬绑定企微；项目已有
  「改名 + 门面转发」成熟范式（README 6.23）。
- **批次拆解**：
  1. 定义 profile schema（JSON）：进程名/启动参数、调试端口范围、UA 指纹、
     窗口标题匹配、选择器策略、下载通道、可用工具子集；
  2. `wecom_bridge/` → `bridge/` 包装层，保留兼容 re-export（`__all__` 契约测试锁住）；
  3. 把散落的企微常量收进内置 `wecom.json` profile，**逐处替换并配行为锁**；
  4. 第二个目标应用（同为 Electron 内核的客户端 / 内部 OA）跑通最小链路。
- **验收**：企微原有评测场景 100% 不退化；profile 切换不需要改任何 Python 业务代码；
  `cdp_is_wecom` 之类的硬编码判定在源码里归零。
- **风险**：技能提示词里的雇主平台名是最隐蔽的耦合（v1.0.750 刚脱敏过一次），
  必须一并参数化，否则换 profile 后模型仍按企微语义行动。

### 方向 3｜任务轨迹回放与可举证报告

- **本轮已给出的地基**：`core/run_trace.py`、`GET /api/runs` + `/api/runs/<id>`（含
  `summarize` 耗时分布）、SSE 旁路 jsonl、`log_event` 的 `[run=]` 前缀、`X-Run-Id` 头。
- **批次拆解**：① 前端任务详情面板消费 `/api/runs/<id>` 渲染时间轴；② 页面快照缩略
  与判定依据入轨（需 D7 的细粒度埋点）；③ 一键导出 HTML/PDF，标注结论来自
  `rule_check.py` 脚本还是模型。
- **验收**：任取一次失败任务，用 run_id 一次查询拿到完整调用链与耗时分布，
  无需翻多份日志（P1-4 验收）；导出报告能区分「脚本判定」与「模型判断」。
- **风险**：前端 18 个数字前缀脚本 + 大量内联 `onclick`，新增面板要动 `index.html`
  与 js，风险与 ES Module 迁移同量级 → 与 `docs/frontend-module-plan.md` 同步排期。

### 方向 4｜场景评测集：从「全绿」到「业务效果不退化」

- **现状**：`model_bench.py` 7 项跑分只覆盖模型层；提示词 / 工具 schema / 压缩策略
  改动没有任何业务级回归，历史上 P0 几乎都靠用户截图反馈才发现。
- **批次拆解**：① 把真实任务脱敏成 fixture（22 份月报批量判定、跑课断点续跑、
  答题交卷、报销单金额校验）；② 定义指标（任务成功率 / 平均轮次 / token 成本 /
  误判率 / 平均完成时间）；③ 接入现有 `_run_pytest_gate` 之后作为**软告警**出对比表；
  ④ 稳定后再对关键场景设「不得退化」硬门槛。
- **验收**：改一次提示词能立刻看到四个核心场景的指标 diff；门槛不自欺
  （fixture 必须脱敏且可复现）。

## 3. 阶段 C 详情

### 方向 2｜技能包标准化 + 可视化流程编排

- **前置**：方向 1 的「可用工具子集」抽象。
- **做法**：`manifest.json` + `prompt.md` + `tools` 声明 + 测试用例 + 版本；导入/导出/
  分享/签名校验复用 `skill_versions.py` 快照回滚；批审流水线抽成可配置 DAG
  （读页 → 抽字段 → `run_rule_check` 判定 → 写报告 → 断点/续跑），新场景用配置接入
  而非改 `services/batch_flow.py`(1990 行)。
- **验收**：新增一个审计场景不需要改 Python；`rule_check.py` 的确定性规则
  （<1ms、零 LLM 成本）能在新场景复用。

### 方向 5｜审批待办中心与计划模式

- **已有**：三档权限、只读模式、审批双因子、后台审批队列、`session-allow`、先出方案、
  本轮新增的 DOM 级硬闸。缺统一入口。
- **做法**：统一待办队列（批量批准/驳回、按规则自动批准白名单、审批有效期与到期失效、
  记录导出）；计划模式 = 先出方案 → 逐步确认/编辑 → 逐步执行，可中途暂停修改。
- **验收**：用户能随时接管任意在跑任务；审批记录可导出举证。
- **注意**：若把 DOM 硬闸升级成「弹确认」，必须按 `deferred.md` D8 配短时凭据，
  否则批准后原样重试会无限弹窗。

### 方向 7｜数据边界看板 + 离线硬开关

- **做法**：每次任务显示「本次哪些内容发给了哪个模型 / 多少 token / 是否命中 PII
  脱敏」（可复用 `usage_stats.py` 与本轮 `run_trace`）；「离线模式」在 **HTTP 客户端层**
  阻断所有非 localhost 出站，而不是只靠配置项。
- **验收**：开启离线开关后，用防火墙/抓包验证零非本机出站；关闭后功能完全恢复。

## 4. 阶段 D 详情（评估性质，不做产品承诺）

### 方向 6｜远程受控 / 轻端，以及跨平台评估

- ① 受控模式：用户显式开启 + 强认证下允许局域网访问，配手机端简易页面做任务下发
  与审批；② 托盘快捷指令 / 全局热键（`close_guard.py` 已有热键基础）；
  ③ **只做架构解耦**：把 Win32 依赖（`os_windows.py`、ctypes 弹窗、DPAPI、WinForms
  托盘、`schtasks` 提权）隔离到 `platform/` 层，再评估 macOS 可行性。
- **边界**：本阶段**不承诺跨平台可用**，解耦本身就降低 Windows 侧耦合度；
  开放局域网前必须先过方向 7 的鉴权与审计复核。

### 方向 8｜团队知识包 + 健康中心

- **团队包**：知识库 / 经验库 / 技能包导出为可共享包（复用本轮
  `core/profile_bundle.py` 的脱敏与完整性校验），支持从内部共享目录导入；
  月报判定.json 与 `audit_history` 扩展成多机构台账与横向对比。
- **健康中心**：把自修复、版本回滚、组件体检、断点续跑、看门狗整合成启动自检摘要 +
  异常自动归因 + 一键导出脱敏诊断包。历史上黑屏 / 绑定失败 / 提权失效都靠人工翻
  日志拼证据链，`run_id` 落地后这块可以直接消费轨迹。
- **验收**：用一次历史故障（如 LLM 挂死）验证健康中心能自动给出归因线索。
